# PPFP — 개인 투자 포트폴리오 관리

여러 포트폴리오를 계층으로 묶어 관리하고, 매수마다 생기는 Lot 단위로 매도하며, 기간별 수익률·손익·비중 변화를 추적하는 웹 앱(PWA)입니다. 상장 종목 시세와 계좌 보유종목은 연결한 증권사 Open API(토스·한국투자·키움·LS·DB·메리츠)에서 받아옵니다.

명세서 1단계(MVP) 범위를 구현했습니다. 실주문은 포함하지 않습니다.

## 기능

| 영역 | 내용 |
| --- | --- |
| 포트폴리오 계층 | 포트폴리오 안에 포트폴리오를 원하는 비율로 포함(DAG). 한 포트폴리오를 여러 상위에 나눠 넣을 수 있고, 할당 합계 100% 초과·순환 연결은 거부 |
| 자산 | 국내·미국 상장 종목(증권사 시세), 부동산·예금·채권·펀드·대안자산·부채(수기 평가) |
| 매수 · 매도 | 매수마다 Lot 생성. 매도 시 직접 선택 / FIFO / LIFO / HIFO / LOFO / 이동평균 중 선택, 저장 전 Lot별 실현손익 미리보기 |
| 기업행위 | 분할·병합·무상증자 시 모든 Lot 수량·단가 일괄 조정 |
| 분석 | 전역 기간 선택(1D~전체, 사용자 지정), 총평가액·기간손익·TWR·최대낙폭·배당이자, 평가액/투자원금 추이, 자산배분(유형·통화), 비중 변화(100% 누적), 하위 포트폴리오 성과 |
| 증권사 연동 | 토스·한국투자·키움·LS·DB·메리츠증권 Open API. 사용자별·계좌별 키와 접근토큰을 AES-256-GCM으로 암호화 저장. 국내·미국 잔고, 현재가·환율·일봉(연결된 곳 중 응답하는 증권사에서) |
| 보유종목 가져오기 | 연결한 계좌의 보유종목을 골라 종목별로 포트폴리오 지정 → 증권사 평균단가로 시작 Lot 생성. 계좌별로 이미 가져온 수량을 기억해 다시 가져오면 차이만 제안. API가 없는 증권사(하나·미래에셋·KB 등)는 잔고 표 붙여넣기·CSV·XLSX 업로드 |
| Export | 포트폴리오 구조·보유·Lot·거래·실현손익·일별 스냅샷을 CSV(엑셀 호환) / XLSX로. 범위·기간 필터 적용 |
| 기타 | 금액 가리기, 상승/하락 색상 반전, 다크 모드, 감사 로그, 홈 화면 설치(PWA) |

## 시작하기

필요: Node.js 20.9+, PostgreSQL 14+

```bash
npm install
cp .env.example .env          # DATABASE_URL, APP_ENCRYPTION_KEY, CRON_SECRET 채우기
npx prisma migrate dev --name init
npm run dev                   # http://localhost:3000
```

`APP_ENCRYPTION_KEY` 생성:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

가입 후 **연동 · 설정**에서 증권사 개발자 포털에서 발급한 앱키/시크릿을 입력하면(한국투자증권은 계좌번호도) 연결을 확인한 뒤 저장합니다. 키는 `.env`가 아니라 사용자마다 앱에 입력합니다. 그다음 **보유종목 가져오기**에서 계좌 보유종목을 포트폴리오에 넣습니다.

| 증권사 | 포털 | 잔고 | 시세·일봉·환율 | 비고 |

| 토스증권 | developers.tossinvest.com | 국내·미국 | ✓ | |

하나증권(1Q Pro, Windows OCX)·NH·삼성·신한·대신(Windows COM)은 웹 서버에서 호출할 수 없고, 미래에셋증권은 공개된 개인용 REST API를 확인하지 못했으며, KB증권(오픈베타)은 문서가 로그인 후에만 공개돼 연동하지 않았습니다. 이 증권사들은 잔고 붙여넣기로 가져옵니다.

## 일별 작업

기간 분석은 하루 한 번 저장하는 스냅샷을 읽습니다. 장 마감 후 아래 중 하나를 실행하세요.

```bash
# 서버 cron (07:10 KST 미국 장 마감 후, 16:10 KST 국내 장 마감 후)
10 7,16 * * 1-5  cd /app && npm run job:daily

# 또는 HTTP 스케줄러
curl -X POST -H "Authorization: Bearer $CRON_SECRET" https://<host>/api/cron/daily
```

과거 거래를 입력한 직후에는 대시보드의 **과거 기록 계산** 버튼이 과거 종가를 받아 첫 거래일부터 스냅샷을 만듭니다.

## 테스트

```bash
npm test         # 계산 엔진 단위 테스트 (외부 패키지 불필요)

```

테스트 대상: 정밀 소수 연산, 포트폴리오 그래프(순환·할당 검증, 롤업), Lot 엔진(6가지 방식, 수수료 배분, 환차 손익, 분할), 거래 재생·일별 시계열, TWR·기간손익·최대낙폭, 기간 계산, CSV, 암호화, 잔고 붙여넣기 파서, 증권사 어댑터(가짜 fetch로 요청 경로·TR·헤더·연속조회·토큰 재발급과 응답 파싱 확인).

## 계산 규칙 요약

- 금액·수량은 부동소수점을 쓰지 않습니다(DB `Decimal`, 코드 `Dec`).
- Lot 단가에는 매수 수수료·세금이 포함됩니다. 매도 수수료·세금은 소진 수량 비율로 각 Lot에 나눕니다.
- 해외 자산 원화 실현손익 = 매도대금×매도환율 − 원가×취득환율 (환차 포함).
- 외부 입출금(입금·출금, 현금 없이 등록한 자산)은 수익률에서 빠지고, 배당·이자는 수익입니다.
- 상위 포트폴리오 금액 = 직접 보유 + Σ(하위 금액 × 할당 비율). 순자산 전체는 모든 포트폴리오를 한 번씩 더합니다.
- 일별 기준은 한국 시간(KST) 날짜입니다.

## 알려진 제한 (MVP)

- 실주문, 리밸런싱 제안, 벤치마크 비교, 거래 Import, 2단계 인증, 로그인 시도 제한은 아직 없습니다.
- 과거 환율은 매일 저장된 값과 거래에 입력한 환율로 계산합니다. 연동 전 기간은 거래 환율 또는 `FALLBACK_USDKRW`를 씁니다.
- 거래 수정은 삭제 후 다시 입력합니다(감사 로그에 원본 보존). 이미 일부 매도된 Lot의 매수 거래는 매도를 먼저 지워야 삭제됩니다.
- 증권사 어댑터는 각 사 공식 문서·예제의 필드명으로 만들고 가짜 응답으로 테스트했지만, 실계좌 키로는 검증하지 않았습니다. 처음 연결할 때 응답이 다르면 **연동 · 설정**의 오류 메시지를 확인하세요.
- 호출 한도는 문서에 있는 값(한투 실전 20회/초·모의 2회/초, LS TR별, 메리츠 API별 10회/초 등)에 맞춰 보수적으로 제한합니다. 토스는 공식 수치를 확인하지 못해 약 8회/초로 제한합니다.
- 해외는 미국(USD) 주식만 다룹니다. 증권사 평균단가로 만든 시작 Lot의 취득 환율은 가져오는 시점의 환율입니다.
- 여러 사용자의 증권사 자격증명을 서비스가 보관·호출하는 방식이 각 증권사 약관상 허용되는지 확인이 필요합니다.
